# NSW barley Ramularia: original-source and design-key audit

## Outcome

The three original NSW DPI resources were downloaded and independently
SHA-256 pinned on 13 November 2026. The two XLSX workbooks contain one `Export`
worksheet each. The measurement file has **240 plot rows and 305 columns**;
the trial-detail workbook has **four trial rows and 19 columns**. All 240
`TrialUnitId` values are present and distinct, with exactly 60 plots per trial.

The audit is **non-inferential**. The three established empirical cases remain
unchanged. Most importantly, the exported `Mainplot`/`Subplot` numbering differs
between 2024 and 2025; the stated methods must be reconciled with those
source keys before choosing experimental error strata or estimating a treatment
effect. This discrepancy is not corrected by relabelling source data.

## Verified design inventory

- Four explicit trial codes: `FPB245WIR`, `FPC245WIR`, `FPB255WIR`, `FPC255WIR`.
- Five blocks per trial and 12 plot records per block.
- Two genotype labels, 120 records each; six fungicide schedules, 40 each.
- The PDF describes 60 plots per experiment and 5 replicates in a split-plot
  design, with fungicide as the main-plot factor and genotype as subplot.

**Unresolved coding conflict:** in each 2024 trial, grouping by
`(TrialAcronym, Block, Mainplot)` produces only ten groups (two Mainplot codes
per block), each containing all six fungicide labels. In each 2025 trial, the
same grouping yields 30 groups (six per block), each containing one fungicide
label and both genotypes. This may reflect an export-code convention or a
year-specific design difference. Its meaning is not established by the source
labels alone. No source records have been changed.

Consequently, model permission remains **requires prespecified estimand and
verified assignment hierarchy**. The 240 rows are not 240 independently
randomized fungicide units; the 2024 coding must be reconciled with the trial
methods and physical allocation before treatment contrasts.

## Reproduce locally

Download the three original files to a directory outside the repository and
install `openpyxl` for local XLSX decoding. Use the checksum-pinned script:

```bash
python -m crop_protection_ps.nsw_barley_intake \
  --trials /path/to/trials.xlsx \
  --measurements /path/to/measurements.xlsx \
  --methods /path/to/methods.pdf \
  --output results/real_nsw_barley_ramularia/source_audit.json
```

Repeat with `--check` to compare regenerated bytes against the committed
derived JSON. CI runs synthetic rejection tests without fetching publisher
resources or requiring `openpyxl`. This stage does not inspect treatment
outcomes, fit a model, or make agronomic recommendations.
